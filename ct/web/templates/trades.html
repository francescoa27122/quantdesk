How this page works (for the curious) Each row is one correlation_id: signal → risk → order → fill → close, reassembled from the event log. Why the event log and not the trades table: nothing in the codebase writes trades — a page built on it would sit permanently empty and read as "no trades yet" rather than "nothing records this". Lifecycles are derived from events that are written, and they carry the rejection reason, the maker ratio and the causal chain, which the table would not.
